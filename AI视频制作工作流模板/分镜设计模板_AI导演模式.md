## 数字规范自检（规定）

每个 Scene 的**旁白全文**定稿后、提交用户审核节点前逐条自检。机器门为 preflight 检查 13（`narration_digits`，`preflight_check.py:1199-1213`：render 模式命中即阻断、audit 模式降级 warning）；本节是**撰写侧**自检——门禁通过不替代本节（白名单只管例外，可读性由人裁定）：

- [ ] 旁白与字幕中的数值一律阿拉伯数字："30小时"、"5%"、"20元"；禁止"三十小时"、"百分之五"形态
- [ ] 例外仅成语（如"三心二意"）与序数（如"第三"）；白名单唯一权威源 `程序文件/配置/config/quality/narration_digits_rules.json`（`idiom_whitelist`），追加例外改该文件或经 config 项目级 `narration_digits_whitelist` 声明——**不得在分镜/旁白里 ad-hoc 开口子**
- [ ] 带 json 两张单位表（`primary_units` / `extended_units`）内单位的量化数值必须全部阿拉伯（此为检查 13 裁定面）；表外单位的中文数字组合不在门禁裁定面，撰写侧按可读性裁定，但不得借此为表内量化项保留中文数字
- [ ] 字幕与旁白同源：旁白数值改动后同步核对字幕数值，只改一侧即分叉

## 常设观感默认（用户裁定 2026-10-10，除非当次另有要求）

| 项 | 默认 | 生效载体（判据住这里，本模板只指路） |
|----|------|--------------------------------|
| 画面底色 | **浅色系**（背景、卡片、装饰层同调） | 分镜「背景」行 + `index.html` CSS；属设计判据，无代码门禁 |
| 背景音乐 | **缺省不配**——用户反对的是那条合成低频 drone（"嗡嗡"），**不是背景音这件事**；悦耳配乐照加，加的是外部音轨 | config `bgm_enabled`，缺省值权威源 `enhance_video_audio.BGM_ENABLED_DEFAULT`（本模板不复述取值）；要配乐须显式声明 `bgm_enabled: true` **且**声明 `bgm_source` 指向曲目文件（外部素材，仓内不含曲库） |
| 字幕样式 | **浅色系底上不加盖**（用户裁定 2026-10-11："灰色背景没必要，破坏画面整体视觉风格"），深色系底仍走半透底盒；字周**无黑色粘连**，全项目统一。**不得只摘盒**——浅底上须同时换深墨字并把描边改成浅色半透，否则白字落在浅底上等于把字幕擦掉 | `enhance_video_audio` 单一生成点，两轴正交：几何档按画布宽、色彩档按**字幕带实测亮度**（阈值住 `video_quality_rules.json`，本模板不复述取值）；项目 HTML/config **不得**自行声明字幕样式，跨项目一致靠代码而非约定 |
| 封面与切点 | 封面上的每个元素都要有**可读时长**（与旁白首句同义的设问句不该放封面上——它没人读得完，交给首场画面）；封面淡出结束到下一场首个元素出现之间**不得留空画面**（经验值 ≤0.3s）；初始 `opacity:0` 的元素必须有对应入场语句，否则全程不可见 | 设计判据，无代码门禁（观感类问题三轮均由用户肉眼抓出、81 项用例 0 抓出，故不再加门禁）；渲染前自查用 `content_vacuum_precheck.py` 的同一 seek 探针在切点前后逐刻截图量测，零渲染 |
| 章级标识 | 分章的信息片（经验阈值：**≥4 章或 ≥5 分钟**）须有**常驻章级标识**＝章序号＋章名＋章进度刻度，固定在画面一角不动。三条约束：① 只用 `opacity` 做时间位切换，切换时刻**锚在既有 T-block 章起点**上；② 不加旁白、不改场景窗口、不引入第三类动画范式（它是画面层改动，不是内容改动）；③ 单章短片不强制——多一块常驻即多一块视觉噪声。动因：观众在中段问"这是第几件事"时画面必须答得上来，否则读作信息过载，而这类流失的病灶是**缺归属标识**而不是每场字数 | 设计判据，无代码门禁（同本表其余观感项）；分镜阶段先在「常设观感默认」本节把 13 场归 4–5 章、章名列表写进分镜表，再在 HTML 里落一个常驻元素。**注意它与增量渲染的关系**：它只加一个 `opacity` 时间位切换的元素、不动 T 块与旁白，按分类器口径属"场景 div 内容变化"，故**预期**下一次纯画面修订可走场景级增量而非全量——该预期尚无自然命中读数（增量在生产上的命中数为 0，见开发仓治理文件的同名登记），按全量估成本才是稳妥做法。 |

> 本表各项的"要不要"由这里裁定，"怎么实现"一律回代码/配置权威源读——在此写死数值即第二个真相源，改代码不会改这里。

## 用户审核节点

以下内容需要用户确认后才能进入 HTML 制作：

1. **图文匹配**：每个场景引用的图片是否与旁白内容匹配？
2. **缺失素材**：标记为“ImageGen 生成”或“跳过”的场景是否可接受？
3. **时间节奏**：各场景时长分配是否合理？有没有太长或太短的？
4. **遗漏素材**：素材盘点中有哪些可用素材没有被分配？
5. **视觉风格**：深色/浅色主题选择、字号体系是否满意？

## config.json 生成（审核通过后执行）

分镜设计审核通过后，生成 config.json 作为渲染流水线输入：

```json
{
  "video_name": "{视频名}",
  "video_duration": {total_seconds},
  "voice": "zh-CN-YunxiNeural",
  "scenes": [
    {
      "id": "scene{N}",
      "narration": "{旁白全文}",
      "window": {start, end},
      "duration": {window_end - window_start}
    }
  ],
  "paths": {
    "html": "{project_name}/index.html",
    "output": "{output_path}"
  }
}
```

生成方式：
- 推荐：`python scene_config_generator.py --narrations narrations.txt --output config.json`
- 手写：AI 根据分镜设计的时间分配表直接生成

## 使用方式

```
Step 1: python asset_scanner.py --project {name}
Step 2: AI 阅读扫描结果 + SDL/旁白，填写本文档
Step 3: 用户审核分镜方案
Step 4: 审核通过 → AI 手写 HTML（参照 HyperFrames_HTML模板参考基准.md）
Step 5: 生成 config.json（scene_config_generator.py 或 AI 手写）
Step 6: preflight_check.py 预检 PASS
Step 7: pipeline_runner.py --config 渲染流水线
```
