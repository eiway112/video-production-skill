# 视频制作新路径 — 系统性踩坑清单与防范检查表

> 本文档是 AI 导演模式（素材盘点→分镜设计→手写HTML→渲染流水线）实施过程中的参照手册。
> 每个关键步骤完成后，对照相关条目逐项检查，确保不重复前期错误。

---

## 一、图片素材类

### 1.1 图片失真
| 项目 | 内容 |
|------|------|
| **问题现象** | 图片被拉伸、压缩、模糊，分辨率与容器不匹配 |
| **历史案例** | 竖版 3:4 照片放入横版 16:9 容器，`object-fit:cover` 裁切掉 58% 内容 |
| **根因** | 容器宽高比与图片原始比例不一致时，CSS `cover` 裁切内容、`contain` 留白 |
| **防范措施** | 见下方"比例适配决策树" |

**比例适配决策树**：
```
图片比例 vs 容器比例：
├─ 保留率 ≥ 60%（如 4:3→16:9）→ object-fit:cover + 焦点裁切
├─ 保留率 < 50%（如 3:4→16:9）→ 模糊背景双层方案：
│   底层：同图 cover + blur(20px) + brightness(0.6) + scale(1.1)
│   上层：原图 contain 居中
└─ 横版→横版（如 16:9→16:9）→ 直接 cover
```

**检查时机**：分镜设计阶段确认每张图片的原始比例和目标容器比例，计算保留率。

### 1.2 容器与图片不匹配
| 项目 | 内容 |
|------|------|
| **问题现象** | 图片显示不完整、大面积空白、被截断 |
| **历史案例** | scene4/scene6 的 split 布局使用 `split-placeholder` 灰色占位区（500px），从未替换为真实图片 |
| **根因** | 编译器不知道项目目录下有什么图片，默认生成占位符 |
| **防范措施** | ① 素材盘点阶段生成完整图片清单 ② 分镜设计阶段每张图片必须指定文件名 ③ HTML 中禁止出现 `[Image]` 占位符 |

**检查时机**：HTML 制作完成后，grep 搜索 `placeholder`、`[Image]`、`src=""` 等占位标记。

### 1.3 图片语义匹配
| 项目 | 内容 |
|------|------|
| **问题现象** | 图片内容与场景旁白无关 |
| **根因** | 仅按文件名匹配，不验证图片实际内容与文案的语义关联 |
| **防范措施** | AI 导演模式下，我读取每张图片的视觉内容，与场景旁白做语义匹配确认 |

**检查时机**：分镜设计阶段，用户确认图文匹配关系。

## 二、时间节奏类

### 2.1 转场/停留时间过长
| 项目 | 内容 |
|------|------|
| **问题现象** | 画面静止 6-8 秒，动画入场完成后画面长时间无变化 |
| **历史案例** | 医院项目 scene1: 35s 窗口，动画 17s 完成，后 18s 几乎静止 |
| **根因** | 编译器只在入场阶段安排动画，入场完成后无持续动效 |
| **防范标准** | 见下方"场景时间设计规范" |

**场景时间设计规范**：
```
场景窗口 = TTS时长 + 场景余量（--shrink-margin）    ← 入场动画与 TTS 并行，不额外占窗口；转场由相邻场景共享

1. 窗口分配：**TTS 占比是场长的派生量，不是设计目标**——窗口 = TTS 时长 + `--shrink-margin` 场景余量（缺省 1.5 s），场越长占比越接近 100%，实测已交付片落在 85-92%。旧口径"TTS 占窗口的 60-75%"（曾写作设计约束，并另列"入场动画 15-25%、过渡 5-10%"三档配比，三档相加 80-110% 本不自洽）与该窗口模型不符，自 2026-10-15 起废弃；它真正想约束的是"不塞 dead-air"，那一约束由 `audio_sync_rules` 的 dead-air 上限与 timeline 步 `--shrink` 实际承担。留白偏松时的收紧入口是 `shrink_basis`，见 §八·补 读法约束④。
2. 入场后填充：必须有持续动效（呼吸/脉冲/数据变化/循环动画）
3. 最大静止时间：任何场景内连续静止不超过 3 秒
4. 转场时间：0.8-1.2s（AGENTS.md 规范）
5. 场景间推移转场自动覆盖过渡区间，无空白
6. 内容动画起始时间 T ≥ 3（封面占 0-3s，主线从 3s 开始）
```

**持续动效模板**（AI 导演在 HTML 手写时选用，必须添加到主 timeline `tl` 上）：
```javascript
// 呼吸脉冲（适用于卡片、光晕）
tl.to(el, { scale: 1.03, opacity: 0.9, duration: 2, repeat: -1, yoyo: true, ease: "sine.inOut" }, T);

// 数据微动（适用于数字、指标）
tl.to(el, { innerHTML: targetValue * 1.02, duration: 3, repeat: -1, yoyo: true, snap: { innerHTML: 1 } }, T);

// 光线漂移（适用于背景光斑）
tl.to(el, { x: "+=30", y: "+=20", duration: 4, repeat: -1, yoyo: true, ease: "sine.inOut" }, T);

// 进度条微进（适用于指标展示）
tl.to(el, { width: "+=2%", duration: 2.5, repeat: -1, yoyo: true }, T);
```

**禁止使用独立 `gsap.to()` / `gsap.fromTo()`**，HyperFrames seek-and-capture 引擎只认 `window.__timelines["main"]`，独立调用不会被渲染捕获。

**检查时机**：分镜设计阶段审核每个场景的时间分配；HTML 完成后检查 GSAP 时间轴是否有 >3s 的无动画区间。

### 2.2 TTS 溢出场景窗口
| 项目 | 内容 |
|------|------|
| **问题现象** | 旁白音频超出场景时间窗口，导致音画不同步 |
| **已有防线** | step7_validate 自动检测（overflow_tol 随视频时长自适应：短视频 0.3s/中视频 0.5s/长视频 0.8s） |
| **前置防范** | scene_config_generator.py 已实现 TTS 驱动窗口计算；adjust_timeline.py 双向调整 |

**检查时机**：Step 0 (TTS 预生成) 后自动检测，失败时运行 adjust_timeline.py。

## 三、字幕与音频类

### 3.1 字幕溢出安全区
| 项目 | 内容 |
|------|------|
| **问题现象** | 字幕与场景内容重叠，或场景内容侵入字幕区域 |
| **历史案例** | 医院项目反复 4 次调整 safe-zone-height（200→280→320→325px）才通过 |
| **根因** | 编译器生成的场景内容高度不可预测，固定安全区高度不够 |
| **成功项目基准** | workflow-promo: 140px, summary: 130px, governance: 130px |

**subtitle-safe 规范（新路径）**：
```
AI 导演手写 HTML 时：
1. 字幕安全区高度：130-140px（成功项目基准，深色主题）
2. .sc 容器 padding-bottom ≥ 安全区高度 + 20px（内容自收缩布局，通常 150-160px）
3. 满高填充布局（flex:1 网格/列表撑满 .sc）：padding-bottom ≥ 240px
   - 视觉边界门禁要求内容底沿 ≤ y=840（对 y=860 安全线留 20px 余量）
   - 历史案例：集成模块隔墙项目 160px 时 6 场景底沿达 y895-918，返工一次 8 分钟渲染
4. 场景内容最大高度 = 1080 - padding-bottom（确保内容不侵入）
5. overflow:hidden 兜底（.sc 必须设置）
6. 禁止为“容纳更多内容”无限放大 safe-zone-height
   - 325px 意味着画面底部 30% 被渐变覆盖 → 视觉破坏
7. 渐变梯度参照成功项目：
   rgba(bg,0) 0% → rgba(bg,0.85) 40% → rgba(bg,0.95) 100%
   不使用过高透明度（如 0.96）导致黑色感过重
```

**检查时机**：HTML 制作后，CSS 审查 padding-bottom 和 subtitle-safe height；渲染后视觉边界检测（y=860 安全线）。

| 项目 | 内容 |

| **问题现象** | 字幕末尾出现句号、逗号等标点，影响阅读观感 |

### 3.4 句界收尾「突兀、局促」，多轮调整停顿与切点都不改善（2026-10-21，一支 194.8s 片子的五轮教训）

| 项目 | 内容 |
|------|------|
| **问题现象** | 人耳点名某一两处句号收尾与下句衔接「局促」。改强制停顿时长、改切点、加淡入淡出，连续三轮无改善甚至更糟；指标（句间静音 0.40s、silencedetect 命中）全部达标 |
| **根因** | TTS 是**一场景一调用**，引擎在同一次调用内还要接着说时，句号处既不释放也不停顿。实测同一句：生产片段 **225ms**、同文本独立合成 **390ms**；切点处 **−17.8 dBFS**（满能量语音），前句末字与下句首字之间**没有能量谷** |
| **机制边界** | 用例111「下刀点收敛到字间隙」**预设间隙存在**。间隙宽度为 0 时它退化为在端点硬切——不是实现缺陷，是它管不到的一类：**没有边界的地方，下游无法造出边界**。同理，淡入淡出只能削弱能量、不能创造停顿 |
| **零成本诊断** | ① 在 `_timeline_manifest.json` 取该句 `rel_start/rel_end` 得片段时长，与「字数 ÷ 实测语速」对比，差值即被压缩量；② 对切点前后各 100ms 按 5ms 帧算 RMS，看有没有谷（无谷＝无声学边界，下游无杠杆）；③ 看同场其它标点处的静音——若顿号处有几百 ms 而句号处 0ms，说明引擎停顿分配与语义边界无关，改标点也不解决 |
| **唯一有效杠杆** | **源头**：把这一句单独成一次调用重新合成（该句结束整次调用，引擎才会释放），再拼回原场景。`_enforce_sentence_pauses` 的字间隙下刀是下游兜底，管不到无间隙的形态 |
| **拼接纪律** | 停顿用生产不变量（`sentence_pause` 400ms）**不自造**；中段保留 30~40ms 自然尾再补零，避免与尾静音叠加；后段 8ms fade-in；**不补偿电平**——句末自然收力是引擎特征，且分位数在该段不稳（实测 p50 −5.8 / p75 +0.9 dB 自相矛盾） |
| **反面记录** | 做 A/B 时曾插入与生产不同的 1.2s 人工静音，被用户当场否决：**A/B 件必须与生产同参数**，否则听的不是生产的问题 |
| **成本** | 单句独立合成是账户余额扣费，需用户明确点头；一次典型验证为 4 次调用（两句各一对照组） |

## 四、视觉质量类

### 4.1 卡片尺寸与内容不协调
| 项目 | 内容 |
|------|------|
| **问题现象** | 卡片过大/过小，文字溢出或大片空白 |
| **根因** | 固定尺寸卡片不随内容量自适应 |
| **设计规范** | 见下方 |

**卡片布局规范**：
```
1. 卡片网格：max-width 1760px，居中
2. 卡片内部：padding 24-32px，gap 16-24px
3. 文字溢出策略：
   - 标题：单行，overflow:hidden + text-overflow:ellipsis
   - 正文：最多 3 行（line-clamp:3），超出缩减字号
4. 字号分层（与 HTML 模板基准一致）：
   - 封面主标题：96-108px / 权重 900
   - 场景标题：48-82px / 权重 800-900
   - 副标题：28-36px / 权重 600-700
   - 卡片标题：20-28px / 权重 700-800
   - 卡片正文：16-22px / 权重 400
   - 标签/注释：18-22px / 权重 600-700
5. 卡片数量与网格：
   - 2 列：适合 2-4 个卡片
   - 3 列：适合 5-6 个卡片
   - 4 列：适合 7-8 个卡片（字号相应缩小）
```

**检查时机**：HTML 制作后，检查每个场景的卡片数量与内容长度是否匹配网格。

### 4.2 装饰层/动画层不突出
| 项目 | 内容 |
|------|------|
| **问题现象** | 装饰元素（光晕/浮点/网格）几乎不可见 |
| **历史案例** | 医院项目 glow 用 `#0077b612`（7% alpha），dot 用 `#00b4d808`（3% alpha） |
| **根因** | 编译器统一套用极低透明度，所有场景装饰层参数完全相同 |

**装饰层规范（新路径）**：
```
AI 导演在 HTML 手写时：
1. 主光晕：opacity 0.08-0.15（与成功项目基准一致）
2. 辅助光效：opacity 0.06-0.10
3. 浮动元素：opacity 0.15-0.30
4. 每个场景的装饰参数应有差异（色相偏移、位置变化、数量调整）
5. 装饰元素底边 ≤ y=840（远离 y=860 安全线）
6. 装饰层不应喧宾夺主——为内容服务，不干扰阅读
7. 长场景（>15s）的 glow 动画用 repeat:-1 而非固定 repeat 值
```

**检查时机**：HTML 制作后，审查装饰元素的 opacity 值；instant_preview 检查动画密度。

### 4.3 底部渐变背景破坏画面
| 项目 | 内容 |
|------|------|
| **问题现象** | subtitle-safe 的深色渐变在浅色场景中形成明显"黑底" |
| **历史案例** | 医院项目（浅色 medical 主题）使用 325px 高、rgba(10,15,30,0.96) 的深色渐变 |
| **根因** | subtitle-safe 颜色固定为深色，不随场景主题适配 |

**subtitle-safe 主题适配规范**：
```
深色主题（#0f172a / #0a0e1a / #0d1117）：
  background: linear-gradient(to bottom, rgba(bg,0) 0%, rgba(bg,0.85) 40%, rgba(bg,0.95) 100%)
  height: 130-140px
  （参照成功项目：workflow-promo 140px, summary 130px, governance 130px）

浅色主题（#f8fafc / #ffffff）：
  background: linear-gradient(to bottom, rgba(0,0,0,0) 0%, rgba(0,0,0,0.35) 40%, rgba(0,0,0,0.55) 100%)
  height: 120-140px
  （用半透明黑色而非深蓝色，避免色偏）

混合主题：
  根据每个场景的背景色动态选择渐变方案
```

**检查时机**：HTML 制作后，确认 subtitle-safe 渐变颜色与场景主题匹配。

### 4.4 content_vacuum 判据被读成"入场太慢"（2026-09-23 篇1 Scene9 两次无效修复）

| 项目 | 内容 |
|------|------|
| **问题现象** | `visual_boundary_check` 报 `content_vacuum`，把 GSAP 入场时间整体提前后真实渲染仅把早期覆盖率从 10% 抬到 11%，第二次全量渲染白费 |
| **判据真实语义** | `measure_content_coverage` 量的是 y∈[120, 860] 带内**被点亮的行占比**（某行 >20 个亮像素即计入，亮像素=R/G>80 或 B>100）。采样 `early_t = start + min(7.5, dur*0.45)`、`late_t = start + dur*0.85`；FAIL 条件 `late_cov ≥ 0.15 且 early_cov < late_cov*0.35` |
| **根因** | 误以为它是"动画节奏"判据。实际是**纵向铺展度**判据：一小条标题+标签在前 7.5s 内即使全部就位，占用行数仍不足 15 行；而 `fromTo` 默认 `immediateRender:true`，seek 到 tween 之前元素恒处隐藏态 |
| **有效修复方向** | 让早期就有**大面积实心内容**立住：高卡片（不是薄条）、实心色脊、剖视图形先行。`scaleY` 类 transform 不改布局高度，"卡架先出、柱形后长"不会引发布局跳动 |
| **无效修复方向** | 单纯压缩 stagger 间隔 / 提前 tween 起点（篇1 第一次即此形态，实测 +1pp） |

**零渲染预判器（渲染前秒级裁定，替代"用全量渲染验证改动"）**：
```
python 程序文件/脚本/content_vacuum_precheck.py <index.html> [sid:start:dur ...]
# 省略场景清单时自动从 HTML 的 var T = {...} 推导全部 ≥6s 场景
```
- 原理：Chrome/Edge 无头 `--screenshot` + URL `?t=` 注入 `tl.pause(); tl.seek(t); gsap.ticker.tick()`；
  采样时刻与门禁同源，覆盖率直接调 `visual_boundary_check.measure_content_coverage`（判据不复制第二份）。
- 校准方式：先用**改前 HTML** 跑预判，读数与已有渲染帧实测对齐（篇1 实测 0.112/0.419 vs 渲染帧 0.112/0.423）后才据以裁定改后效果。
- `instant_preview.py` **不能**替代它：预览每场只取 `start+3.0` 与 `end-2.0`，与门禁采样时刻不同。
- **要看别的时刻就点名要，别另写探针（2026-10-26 起）**：`instant_preview.py --times 62.5,88` 按绝对秒逐枚全幅截图，落项目 temp 的 `preview_frame_<秒>.png`。两点采样盖不到的形态（场初浮空箭头、批注压安全线）用它看；**网格图是缩略图**，判版式要看全幅帧。越界时刻（≥ `video_duration`）直接报错——截到片尾之后会得到封面帧/黑帧，那种读数容易被误读成"画面缺失"。
- 探针与 `gsap.min.js` 必须同目录（缺 gsap 会静默全帧空白）；工作目录取根目录同盘的 ASCII 路径（根目录含中文时 file:// 注入不可靠）。
- 退出码 2 表"无从裁定"（缺浏览器/注入失败/取数异常），不得读成通过。

### 5.2 渲染纪律
| 变更类型 | 验证手段 | 是否需要重新渲染 |
|----------|---------|:---:|
| HTML 图片替换 | preflight 确认图片存在 | 是（仅 Step 1） |
| GSAP 时间调整 | preflight 确认时间戳 | 是（Step 0-2） |

| BGM 调整 | --quick-fix | 否 |
| cue 点亮形态 / 结构化图形骨架（纯 HTML 层） | `instant_preview.py` 截图自查即可裁定——`CUE-MAP` 常驻 HTML，预览期 cue 真实执行（§4.5） | 是，但**只付一次**：自查在预览面完成，禁止"改一次渲一次"地用全量渲染当预览 |

> ⚠️ **--quick-fix 产物不可用于交付验收**：quick-fix 会把 preflight→visual_check 标记为 skipped，
> 完工报告门禁要求各步 passed=true，会拒绝认证（历史案例：集成模块隔墙项目 quick-fix 后
> 报告 FAILED，5/11 项被拒）。交付前必须全链真实跑通（--resume / --fresh）。

### 5.3 连续修复止损与换层判据（2026-10-21 加强）
- 同一问题连续修复 **超过 3 次** → 停止，输出阻塞报告
- 禁止在未获得用户新方向前继续堆叠修复尝试
- **「停止」不等于「结案」**：止损时第一件事不是写"无解"，而是判**当前这一层还有没有杠杆**。判据＝这一层操作的物理上限能否触及病灶——例如在音频里加静音，最多让声音"断得干净"，不能造出原本不存在的能量谷；在字幕层改时间，改不动合成时的发音。答完再决定：换层，或明确写"该问题在现有链路内不可解"。
- **同一处第 2 次修补仍不改善 → 判「本层无杠杆」，必须换层**；第 4 轮必须已经换到源头层。同一层连续三轮以上＝把成本花在同一堵墙上（2026-10-21 实证：下游四轮全部落空，第五轮回到源头一次即成）。
- **观感类问题以人耳结案，不以量化指标结案**。指标只回答"测到了什么"，不回答"应当怎样"；指标改善而人耳否决时，以人耳为准并回头查指标是否量错了对象。**禁止拿指标改善去说服用户接受观感**（本轮三次指标达标、人耳三次否决）。
- 分层次序（由近及远，代价递增）：下游后处理 → 强制停顿/切点参数 → 共享机制代码 → 源头重合成（付费）→ 换引擎。**每上一层都要先证下一层无杠杆**，而不是凭习惯从最近的那层一路试到底。

### 5.7 跨结构边界的大段文档编辑：三次"替换时把边界另一侧一并删掉"（2026-10-17 同批自证）

| 项目 | 内容 |
|------|------|
| **问题现象** | 一次向三份模板文档插入长段落时，三次把"只在某锚点之后追加"做成了"替换掉锚点及其相邻结构"：① 下一节的 `## 五、…` 标题整行消失；② 表格后那句"本表各项…只指路"的免责句消失；③ 上一节代码块的尾部三行与闭合围栏消失（代码块被截在半截 HTML 里）。三次均由编辑者自身写法造成，与被编辑内容无关 |
| **根因（单一形态）** | 用"跨结构边界的多行 old_string"做锚：锚串同时圈进了**标题行／表格尾句／代码围栏闭合**这类结构件，替换串却没带它们 → 它们随替换一起消失。锚越长越"稳"的直觉在这里正好反向——长锚的唯一作用是多吞几行 |
| **防范措施（写法层）** | ① 插入类编辑一律用**单行唯一锚**：`old = 锚行`、`new = 锚行 + 新内容`，锚不得跨标题行、表格行、代码围栏这三类边界；② 表格新增行必须紧贴同表上一行（表内插空行即断表），列数与表头一致；③ 新段落若要接在上一节末尾，锚取上一节**内容行**而非节标题 |
| **防范措施（机算层，编辑后必跑，不靠肉眼）** | 一次纯新增批的终态判据：**删除行数 == 0**。用去 CR 归一化后跑 `difflib.unified_diff(HEAD版, 工作树版)`，删除行非 0 时逐条打印并核其确属"有意改写"而非被吞；再核两件事——章节标题集合的前后差集为空、代码围栏 ``` 计数为偶数。本批三次事故全部由这套对账当场显形并修回 |
| **行尾陷阱（同批实测，勿误读）** | 本仓部分 md 的 blob 是 CRLF（根 `.gitattributes` 落地前提交），首次编辑这类文件时 `git diff` 会呈**整档重写**（`text=auto` 在 diff/提交时把工作树归一为 LF），而真实内容改动可能只有十几行。判据：跨态比对一律先去 CR 再算差异（与 AGENTS.md「跨仓比对一律用去 CR 后的内容哈希」同口径），并在提交说明里点名这次归一，否则日后读 diff 会误判为整档改写 |

        节点大样——这类画面一旦被观众当作实物依据，AI 图的构造错误就是技术错误
4. 识别"未使用素材" → 确认是有意排除还是遗漏
```

### 6.2 分镜设计审核节点
```
AI 导演在分镜设计阶段输出：
1. 每个场景的画面构成描述（用什么图、什么布局、什么动效）
2. 每个场景的时间分配（TTS 占比、动画占比、过渡占比）
3. 素材引用表（场景号 → 图片文件名 → 展示方式）

用户在此节点确认：
- 图文匹配是否正确
- 时间节奏是否合理
- 是否有遗漏的重要素材
```

### 八·补：TTS 语速实测基准（`duration_budget` 声明的唯一估算口径）

**为什么单列一条**：`agent-decision-map`（2026-10-12）按"5.0 发音字符/秒"反推声明预算 235 s，成片实测 253.8 s，超预算 18.8 s 走 `--accept-over-budget` 放行留痕——偏差全部来自这个手抄常数，不来自内容超载（13 场 65–94 发音字符，已按每场 60–70 字基准收紧）。预算写低会让每一次正常交付都需放行，放行留痕便失去"异常情况"的含义。

| 口径 | 定义 | 实测值（qwen cosyvoice-v3-flash + `longanling_v3`，rate +5%） | 用途 |
|------|------|:---:|------|
| 纯语音率 | 发音字符 ÷ Σ(各场 TTS wav 时长) | **4.33 字符/秒**（1002 / 231.3；逐场 3.86–4.97，中位 4.28） | 估单场窗口下限、估句间停顿余量 |
| **成片折算率** | 发音字符 ÷ `video_duration` | **3.87–3.95 字符/秒**（三样本：`agent-decision-map` 1002/253.8=3.95、`standard-system-explainer` 1221/313.2=3.90、`prefab-decor-delivery` 1576/407.6=3.87） | **声明 `duration_budget` 用这一档，取 4.0 作上界** |

**读法约束**：①"发音字符"＝归一化后保留的发音字符数（`cue_resolve.normalize` / `_forced_align._normalize_chars` 口径），**不是**源文本 `len()`——标点与空格不进 TTS 时长；②两档之间差的不是语速而是**留白**（本片 13 场合计约 19.5 s 场景窗口留白＋3 s 封面），所以"4.3 字符/秒 + 每场留白"与"4.0 字符/秒"等价，选用哪档取决于是否已逐场排窗口；③换音色/换 `qwen_model`/改 `rate` 后本表数值不适用，须用当轮 `_timeline_manifest.json` 的 `tts_duration` 重算，不得沿用到新项目；④**排完窗口觉得"每场说完还空一下"时，收紧入口是 `shrink_basis`，不是调小 `shrink_margin`**——那 2 s 听感留白由"设计值 1.5 s"＋"wav 尾部静音 0.31–0.46 s"两段构成，前者是本参数动不了的、要动须另一次裁定，后者可由项目 config 顶层 `"shrink_basis": "speech_end"` 收回（本片实测 4.66 s＝片长 1.84 个百分点）。判据与缺省为何未翻住根治理文件「场景余量的基准」节，本处只放指针不复述。

**反例（禁止）**：按参考片或经验"每秒 5 字"反推预算；把 `len(narration)`（含标点）当分子。

**关键发现**：成功项目的 subtitle-safe 高度均在 130-140px，而医院项目膨胀到 325px 是编译器内容溢出控制的失败，不是 safe-zone 设计的问题。
