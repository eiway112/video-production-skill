# 视频制作新路径 — 系统性踩坑清单与防范检查表

> 本文档是 AI 导演模式（素材盘点→分镜设计→手写HTML→渲染流水线）实施过程中的参照手册。
> 每个关键步骤完成后，对照相关条目逐项检查，确保不重复前期错误。

## 一、图片素材类

### 1.1 图片失真
| 项目 | 内容 |
|------|------|
| **问题现象** | 图片被拉伸、压缩、模糊，分辨率与容器不匹配 |
| **历史案例** | 竖版 3:4 照片放入横版 16:9 容器，`object-fit:cover` 裁切掉 58% 内容 |
| **根因** | 容器宽高比与图片原始比例不一致时，CSS `cover` 裁切内容、`contain` 留白 |
| **防范措施** | 见下方"比例适配决策树" |

**比例适配决策树**：
```
图片比例 vs 容器比例：
├─ 保留率 ≥ 60%（如 4:3→16:9）→ object-fit:cover + 焦点裁切
├─ 保留率 < 50%（如 3:4→16:9）→ 模糊背景双层方案：
│   底层：同图 cover + blur(20px) + brightness(0.6) + scale(1.1)
│   上层：原图 contain 居中
└─ 横版→横版（如 16:9→16:9）→ 直接 cover
```

**检查时机**：分镜设计阶段确认每张图片的原始比例和目标容器比例，计算保留率。

### 1.2 容器与图片不匹配
| 项目 | 内容 |
|------|------|
| **问题现象** | 图片显示不完整、大面积空白、被截断 |
| **历史案例** | scene4/scene6 的 split 布局使用 `split-placeholder` 灰色占位区（500px），从未替换为真实图片 |
| **根因** | 编译器不知道项目目录下有什么图片，默认生成占位符 |
| **防范措施** | ① 素材盘点阶段生成完整图片清单 ② 分镜设计阶段每张图片必须指定文件名 ③ HTML 中禁止出现 `[Image]` 占位符 |

**检查时机**：HTML 制作完成后，grep 搜索 `placeholder`、`[Image]`、`src=""` 等占位标记。

### 1.3 图片语义匹配
| 项目 | 内容 |
|------|------|
| **问题现象** | 图片内容与场景旁白无关 |
| **根因** | 仅按文件名匹配，不验证图片实际内容与文案的语义关联 |
| **防范措施** | AI 导演模式下，我读取每张图片的视觉内容，与场景旁白做语义匹配确认 |

**检查时机**：分镜设计阶段，用户确认图文匹配关系。

## 二、时间节奏类

### 2.1 转场/停留时间过长
| 项目 | 内容 |
|------|------|
| **问题现象** | 画面静止 6-8 秒，动画入场完成后画面长时间无变化 |
| **历史案例** | 医院项目 scene1: 35s 窗口，动画 17s 完成，后 18s 几乎静止 |
| **根因** | 编译器只在入场阶段安排动画，入场完成后无持续动效 |
| **防范标准** | 见下方"场景时间设计规范" |

**场景时间设计规范**：
```
场景窗口 = TTS时长 + 场景余量（--shrink-margin）    ← 入场动画与 TTS 并行，不额外占窗口；转场由相邻场景共享

1. 窗口分配：**TTS 占比是场长的派生量，不是设计目标**——窗口 = TTS 时长 + `--shrink-margin` 场景余量（缺省 1.5 s），场越长占比越接近 100%，实测已交付片落在 85-92%。旧口径"TTS 占窗口的 60-75%"（曾写作设计约束，并另列"入场动画 15-25%、过渡 5-10%"三档配比，三档相加 80-110% 本不自洽）与该窗口模型不符，自 2026-10-15 起废弃；它真正想约束的是"不塞 dead-air"，那一约束由 `audio_sync_rules` 的 dead-air 上限与 timeline 步 `--shrink` 实际承担。留白偏松时的收紧入口是 `shrink_basis`，见 §八·补 读法约束④。
2. 入场后填充：必须有持续动效，且**至少一条来自下方 A 组（信息层）**——只挂 B 组装饰层（呼吸/脉冲/循环）＝写了等于没写（实测：某浅色交付件 42 块持续动画里 34 块挂的是背景光斑 `scale`，成片画面静止占比仍达 69%）
   **补两条配额（2026-11-05 编排面实测后立，读数见裁定文档 §十四）**：
   ① **推进型时间配额**——一场里"会走完的动效"（有终点的 `to`/`fromTo`，非无限循环）须覆盖该场窗口的大部分，
      且**任何 ≥3 秒的片段内至少有一条推进型动效正在跑**。全仓实测分布（探针与常驻件两值、口径与更正史
      一律住 `外部参考片实测与借鉴裁定_20261105.md` §14.6／§14.8，本处不复述数值——复述过一次，代码改口径时这里就会过期）——即病灶不是"没写动画"（64/74 项目有 yoyo、每场 12 路），
      是"写的东西里不到四分之一在推进"。
   ② **`repeat:-1`／`yoyo` 循环不得充当填充**：含循环的覆盖率 p50 = **1.000**，是假量；
      同两支成片对撞，纸面填满、像素面只有 25.5%／30.7% 在动（声明面与产出面背离的第三次独立支撑）。
3. 最大静止时间：任何场景内连续静止不超过 3 秒（**该条设立后从未被机算验证过**；2026-11-05 首次复算，两支用户验收通过的横屏成片静止占比 69.3%／74.5%，即绝大多数时间连续静止远超 3 秒。现行自查入口＝完工报告 `data_sources.frame_occupancy.motion` 的在动占比与最长静止秒数，属描述面、不裁定——与"不为观感新增代码门禁"的常设裁定同向，见 AGENTS.md 画面占用行）
   **渲染前另有一腿（同日补，已常驻化）**：本条此前只有成片像素面能查，即"要等一次全量渲染才知道有没有违反"。
   编排面（静态解析 HTML 的时间锚＋`duration` 求并集）可在**渲染前**给同一条的覆盖率与最长无推进段，
   口径、两条取数边界（锚点越界不计入、相对锚未解析故为**下界**）与探针住裁定文档 §14.2；
   常驻形态＝完工报告 `data_sources.choreography`（`choreography_profile.py`，**描述面不裁定**，
   与 `frame_occupancy` 同族、与 2026-10-10"不为观感新增代码门禁"常设裁定同向），用例122 锁定（§十四 编号 25 已落地）。
4. 转场时间：0.8-1.2s（AGENTS.md 规范）
5. 场景间推移转场自动覆盖过渡区间，无空白
6. 内容动画起始时间 T ≥ 3（封面占 0-3s，主线从 3s 开始）
```

**持续动效模板**（AI 导演在 HTML 手写时选用，必须添加到主 timeline `tl` 上）。**按挂载对象分两组，顺序即优先级**：

```javascript
// ── A 组｜信息层（观众能看出"它在跟着讲的东西动"）——优先做这组 ──
// A1 永动底·相机微位移：挂在**场景根**（选择器须含 `#sceneN`，以便增量渲染按归属判到单场），
//    时长取该场窗口，ease 用 none（yoyo 的往复在此读作"晃"而非"推"）
tl.to('#scene4 .sc-body', { scale: 1.02, x: -16, y: -10,
                            duration: (S.s4.end - S.s4.start), ease: "none" }, T.s4);
// A2 跟随讲解的强调：被念到的条目描边/底色亮起，时刻取词级 cue（§3.6 语法）
cue('锚词', () => tl.to('#s5-item3', { borderColor: "#f59e0b", duration: 0.3 }, '<'));
// A3 笔画式高亮：记号笔从左到右扫过正在说的那一行（scaleX 0→1，transform-origin 左）
tl.fromTo('#s5-mark2', { scaleX: 0 }, { scaleX: 1, duration: 0.6, ease: "power2.out" }, T.s5 + 3.2);
// A4 进度/时间轴推进：随该场旁白线性走完，勿用循环（循环读作"没在推进"）
tl.fromTo('#s6-rule', { scaleX: 0 }, { scaleX: 1,
                    duration: (S.s6.end - S.s6.start), ease: "none" }, T.s6);
// A5 跨场常驻主图（锚＋生长）：一张主图**在每一场各画一份、位置尺寸逐字相同**，
//    新内容作为生长层加在它上面——参考片那种"一个 Router 圆活过整章"的观感由此产生。
//    契约属性 `data-anchor="<图形名>"` 是**必填**的：同一名值＝同一张图，完工报告据此
//    量"声明几处／覆盖几场／同不同形"（`data_sources.choreography.persist`，描述面不裁定）。
//    几何写**内联 style**，不写进 <style> 类规则：改 <style> 会动 `outside_scene_hash`
//    → 必判全量渲染；改场内元素的内联样式属场景 div 内容变化，才可能走增量。
<div id="scene3" data-scene-id="s3">
  <div class="base-wall" data-anchor="wall-section"
       style="position:absolute;left:96px;top:150px;width:420px;height:230px"></div>
  <div class="leaf" id="s3-layer1">…本场新增内容…</div>      <!-- 生长层 -->
</div>
<div id="scene4" data-scene-id="s4">
  <div class="base-wall" data-anchor="wall-section"
       style="position:absolute;left:96px;top:150px;width:420px;height:230px"></div>  <!-- 逐字同形 -->
  <div class="leaf" id="s4-layer2">…在基形上长出的第二层…</div>
</div>
tl.fromTo('#s4-layer2', { opacity: 0, y: 14 }, { opacity: 1, y: 0, duration: 0.5 }, T.s4 + 1.2);

// A6 词级 cue 焦点轨（2026-11-08 观感批）：把 A2 从"说到才亮一下"升级成"说到哪、焦点跟到哪，
//    并保持在那一块上"。一个 cue 同时负责点亮 + 保持区间轻微呼吸；呼吸**有限次**、
//    `seg×reps==hold` 铺满到下一锚（下一 cue 或本场窗口末），永不使用 `repeat:-1`。
//    完整骨架、四条原因与写法提醒住 HyperFrames_HTML模板参考基准.md §3.6.2。
cueHi('#s5-item3', 's5:三个条件', T.s5, T.s5 + 16.1);   // (选择器, CUE-MAP 键, T.场, 入场完成时刻)
flushCuePlan();                                          // 构造时间轴的 script 末尾调用一次

// ── B 组｜装饰层（**不计入画面活跃度**，只作填充，不得单独作为本场的持续动效）──
// 呼吸脉冲（适用于卡片、光晕）
tl.to(el, { scale: 1.03, opacity: 0.9, duration: 2, repeat: -1, yoyo: true, ease: "sine.inOut" }, T);

// 数据微动（适用于数字、指标）
tl.to(el, { innerHTML: targetValue * 1.02, duration: 3, repeat: -1, yoyo: true, snap: { innerHTML: 1 } }, T);

// 光线漂移（适用于背景光斑）
tl.to(el, { x: "+=30", y: "+=20", duration: 4, repeat: -1, yoyo: true, ease: "sine.inOut" }, T);

// 进度条微进（适用于指标展示）
tl.to(el, { width: "+=2%", duration: 2.5, repeat: -1, yoyo: true }, T);
```

**A1 的两条风险（照抄前必读，别等渲染才发现）**：
① `scale` 会把内容顶进字幕预留带——写完先跑 `instant_preview.py`（零渲染，安全线按实测画布高等比推导），溢出即在预览期退出码 2，别把全量渲染当预览用；顶不住就只留 `x/y` 平移、把 `scale` 降到 1.01 或去掉。
② 选择器**必须**含 `#sceneN` 前缀。写成全局 `tl.to('#root …')` 或不带场景归属的选择器，`scene_patch_render` 按"脚本变更归属判据"会退回全量渲染（跨场 helper／全局根同理），一条观感修订就多付一次全量。

**A5 的三条风险（2026-11-05 编号 26 实测后立，读数与两条拓扑的对撞住裁定文档 §14.7）**：
① **别把基形放到场景 div 之外**。仓内唯一先例是章级标识 `#chapter`（场景外常驻层），它使该项目的动效语句按 `resolve_selector` 判 `selector-outside-scenes`，实证读数 `standard-system-explainer`：`scene_patch = {verdict: FULL, reason: html-outside-scenes-changed, attempts: 5, hits: 0}`，累计 6 次全量渲染。**"常驻"这件事本身不贵，放错拓扑才贵**。自查：`data_sources.choreography.persist.outside_scene_instances > 0` 即有此形态。
② **漏场或坐标漂移＝观众读作"图跳了一下"**。基形必须在**该锚覆盖的每一场**都在位、内联几何逐字相同；差一个 `top` 就是另一张图。自查：`persist.anchors_geometry_divergent`；某场用类规则而另一场用内联样式时该锚进 `anchors_geometry_unchecked`（**无从判定，不是没问题**）。
③ **按章常驻，别按全片常驻**。增量渲染的准入是 `len(changed)*2 > 场数` 即退回全量（判据住 `scene_patch_render.py:895`，此处不复述结论）：一个锚覆盖一半以上场次时，任何触及它的修订必判 FULL。`persist.largest_anchor_scene_share` 给的就是这个比例，供人对照，本面不裁定。
④ **基形内联 `opacity:0` 而没有入场语句＝这块图在成片里全程不存在**（2026-10-13「6 块内容永久不可见」同病灶）。这一格**没有阻断式门禁兜着**：`check_element_reveal` 只认「容器隐藏·入场只打子元素」形态，`check_scene_visibility` 管的是场景根，两者对本形态实测都判 0——而当时 `persist` 报的是「声明 2 处／覆盖 2 场」，读起来像已就位。自查位点＝`data_sources.choreography.persist` 的 `hidden_instances`（内联请求了初始隐藏）与 `hidden_instances_without_entrance_target`（且任何 tl 语句目标串里找不到它的 #id／·class），后者非 0 就去补入场语句或去掉内联隐藏。
⑤ **前提：场景容器须是定位元素**（仓内规范 `.sc{…position:relative}`；实测全仓 74/74 已满足）。基形按骨架用 `position:absolute` 挂在场景内，容器若不定位，它会挂到更外层——既错位，又等于意外走回①那条「放场景外」的贵路线。

**A6 焦点轨的五条风险（2026-11-08 观感批，由一支用户反馈"长时间停在某个画面上不动"的成片实测换得）**：
① **一次入场就完事＝节奏断档**。入场动画只有 0.5s，旁白这一句还要念 8s，中间 7.5s 画面全停。实测（395s 成片）：在动占比 10.2%、最长连续静止 7.9s、>5s 静止段 3 处，而每个元素都有入场动画——**"写了动画"不等于"画面在动"**。保持区间必须有语句，且铺满。
② **`repeat:-1` 不得用来铺保持区间**。它不计入推进型覆盖率（假满分），而且在渲染 seek 下无限循环与"停在某一帧"的观感差别取决于相位，不可预期。用有限次 `seg×reps==hold`，单段 ≤0.7s（2s 一次的呼吸读作静止）。
③ **保持呼吸的 `scale` 会顶字幕安全线**：先跑 `instant_preview.py`；顶不住就降到 1.02 或只走 `x/y`（与 A1 风险①同判据）。本轮取 1.032 是预览实测通过后的值，不是通用值。
④ **选择器必须含 `#sceneN`**（与 A1 风险②同判据）；焦点锚若写在跨场辅助函数里、按数据驱动执行，**静态解析看不见它的覆盖**，必须以产出面复核。
⑤ **空档补拍的声明挂在子元素上**。旁白在某个点停留 6s 以上而中间没有新元素要亮时，重亮既有元素（不是新造）；若挂到带 `.rv{opacity:0}` 的容器上，会命中 `check_element_reveal` 的形态①/③（入场只打子元素／只有 `from()` 命中）。

**禁止使用独立 `gsap.to()` / `gsap.fromTo()`**，HyperFrames seek-and-capture 引擎只认 `window.__timelines["main"]`，独立调用不会被渲染捕获。

**检查时机**：分镜设计阶段审核每个场景的时间分配；HTML 完成后两腿自查——渲染**前**用 `choreography_profile.py`（零渲染，覆盖率、常驻锚声明面与 **cue 节拍 `cue_beats`**），渲染**后**用完工报告 `data_sources.frame_occupancy.motion`（像素面，含 **`static_windows` 静止窗清单**：停顿停在哪一段，而不只是停了多久）。两腿不得互替：含循环的覆盖率 1.000 而像素面只有 25.5% 在动，是实测形态而非比喻。cue 节拍与静止窗同样要对着读——长 cue 间隔不等于静止（那一段可能有位移/进度类推进），它给的是"去查那一段"的位置。

## 三、字幕与音频类

### 3.1 字幕溢出安全区
| 项目 | 内容 |
|------|------|
| **问题现象** | 字幕与场景内容重叠，或场景内容侵入字幕区域 |
| **历史案例** | 医院项目反复 4 次调整 safe-zone-height（200→280→320→325px）才通过 |
| **根因** | 编译器生成的场景内容高度不可预测，固定安全区高度不够 |
| **成功项目基准** | workflow-promo: 140px, summary: 130px, governance: 130px |

**subtitle-safe 规范（新路径）**：
```
AI 导演手写 HTML 时：
1. 字幕预留带由安全线推导，**不由渐变装饰高度反推**：
   权威源 visual_boundary_check.subtitle_safety_line（1080→y860、1920→y1529）
   ⇒ 1080 画布预留带 220px；门禁判据是 content_bottom ≤ 860（零余量也过）
2. .sc padding-bottom ≥ 240px（预留带 220 ＋ 20px 设计余量），**不分容器是否自收缩**
   - 旧写法给"内容自收缩布局"放宽到 150-160px：那只在内容恰好短时不侵入，
     而"内容短"正是留白事故的同一成因，故两条分支合并为一条（2026-11-11）
   - 历史案例：集成模块隔墙项目 160px 时 6 场景底沿达 y895-918，返工一次 8 分钟渲染
3. 内容场 .sc 顶对齐＋余高由 flex:1 的图形区吸收，不写 justify-content:center
   （居中容器的高度由内容自然高决定 ⇒ 留白对称摊到上下，加大卡片治不了；
     同口径实测三组读数见 HyperFrames_HTML模板参考基准.md §2.2）
4. 场景内容最大高度 = 1080 − padding-top − padding-bottom（确保内容不侵入）
5. overflow:hidden 兜底（.sc 必须设置）
6. 禁止为“容纳更多内容”无限放大 safe-zone-height
   - 325px 意味着画面底部 30% 被渐变覆盖 → 视觉破坏
7. 渐变梯度参照成功项目：
   rgba(bg,0) 0% → rgba(bg,0.85) 40% → rgba(bg,0.95) 100%
   不使用过高透明度（如 0.96）导致黑色感过重
```

**检查时机**：HTML 制作后，CSS 审查 padding-bottom 和 subtitle-safe height；渲染后视觉边界检测（y=860 安全线）。

### 3.4 句界收尾「突兀、局促」，多轮调整停顿与切点都不改善（2026-10-21，一支 194.8s 片子的五轮教训）

| 项目 | 内容 |
|------|------|
| **问题现象** | 人耳点名某一两处句号收尾与下句衔接「局促」。改强制停顿时长、改切点、加淡入淡出，连续三轮无改善甚至更糟；指标（句间静音 0.40s、silencedetect 命中）全部达标 |
| **根因** | TTS 是**一场景一调用**，引擎在同一次调用内还要接着说时，句号处既不释放也不停顿。实测同一句：生产片段 **225ms**、同文本独立合成 **390ms**；切点处 **−17.8 dBFS**（满能量语音），前句末字与下句首字之间**没有能量谷** |
| **机制边界** | 用例111「下刀点收敛到字间隙」**预设间隙存在**。间隙宽度为 0 时它退化为在端点硬切——不是实现缺陷，是它管不到的一类：**没有边界的地方，下游无法造出边界**。同理，淡入淡出只能削弱能量、不能创造停顿 |
| **零成本诊断** | ① 在 `_timeline_manifest.json` 取该句 `rel_start/rel_end` 得片段时长，与「字数 ÷ 实测语速」对比，差值即被压缩量；② 对切点前后各 100ms 按 5ms 帧算 RMS，看有没有谷（无谷＝无声学边界，下游无杠杆）；③ 看同场其它标点处的静音——若顿号处有几百 ms 而句号处 0ms，说明引擎停顿分配与语义边界无关，改标点也不解决 |
| **唯一有效杠杆** | **源头**：把这一句单独成一次调用重新合成（该句结束整次调用，引擎才会释放），再拼回原场景。`_enforce_sentence_pauses` 的字间隙下刀是下游兜底，管不到无间隙的形态 |
| **拼接纪律** | 停顿用生产不变量（`sentence_pause` 400ms）**不自造**；中段保留 30~40ms 自然尾再补零，避免与尾静音叠加；后段 8ms fade-in；**不补偿电平**——句末自然收力是引擎特征，且分位数在该段不稳（实测 p50 −5.8 / p75 +0.9 dB 自相矛盾） |
| **反面记录** | 做 A/B 时曾插入与生产不同的 1.2s 人工静音，被用户当场否决：**A/B 件必须与生产同参数**，否则听的不是生产的问题 |
| **成本** | 单句独立合成是账户余额扣费，需用户明确点头；一次典型验证为 4 次调用（两句各一对照组） |

### 4.4 content_vacuum 判据被读成"入场太慢"（2026-09-23 篇1 Scene9 两次无效修复）

| 项目 | 内容 |
|------|------|
| **问题现象** | `visual_boundary_check` 报 `content_vacuum`，把 GSAP 入场时间整体提前后真实渲染仅把早期覆盖率从 10% 抬到 11%，第二次全量渲染白费 |
| **判据真实语义** | `measure_content_coverage` 量的是 y∈[120, 860] 带内**被点亮的行占比**（某行 >20 个亮像素即计入，亮像素=R/G>80 或 B>100）。采样 `early_t = start + min(7.5, dur*0.45)`、`late_t = start + dur*0.85`；FAIL 条件 `late_cov ≥ 0.15 且 early_cov < late_cov*0.35` |
| **根因** | 误以为它是"动画节奏"判据。实际是**纵向铺展度**判据：一小条标题+标签在前 7.5s 内即使全部就位，占用行数仍不足 15 行；而 `fromTo` 默认 `immediateRender:true`，seek 到 tween 之前元素恒处隐藏态 |
| **有效修复方向** | 让早期就有**大面积实心内容**立住：高卡片（不是薄条）、实心色脊、剖视图形先行。`scaleY` 类 transform 不改布局高度，"卡架先出、柱形后长"不会引发布局跳动 |
| **无效修复方向** | 单纯压缩 stagger 间隔 / 提前 tween 起点（篇1 第一次即此形态，实测 +1pp） |

**零渲染预判器（渲染前秒级裁定，替代"用全量渲染验证改动"）**：
```
python 程序文件/脚本/content_vacuum_precheck.py <index.html> [sid:start:dur ...]
# 省略场景清单时自动从 HTML 的 var T = {...} 推导全部 ≥6s 场景
```
- 原理：Chrome/Edge 无头 `--screenshot` + URL `?t=` 注入 `tl.pause(); tl.seek(t); gsap.ticker.tick()`；
  采样时刻与门禁同源，覆盖率直接调 `visual_boundary_check.measure_content_coverage`（判据不复制第二份）。
- 校准方式：先用**改前 HTML** 跑预判，读数与已有渲染帧实测对齐（篇1 实测 0.112/0.419 vs 渲染帧 0.112/0.423）后才据以裁定改后效果。
- `instant_preview.py` **不能**替代它：预览每场只取 `start+3.0` 与 `end-2.0`，与门禁采样时刻不同。
- **要看别的时刻就点名要，别另写探针（2026-10-26 起）**：`instant_preview.py --times 62.5,88` 按绝对秒逐枚全幅截图，落项目 temp 的 `preview_frame_<秒>.png`。两点采样盖不到的形态（场初浮空箭头、批注压安全线）用它看；**网格图是缩略图**，判版式要看全幅帧。越界时刻（≥ `video_duration`）直接报错——截到片尾之后会得到封面帧/黑帧，那种读数容易被误读成"画面缺失"。
- 探针与 `gsap.min.js` 必须同目录（缺 gsap 会静默全帧空白）；工作目录取根目录同盘的 ASCII 路径（根目录含中文时 file:// 注入不可靠）。
- 退出码 2 表"无从裁定"（缺浏览器/注入失败/取数异常），不得读成通过。

**入场偏移溢出裁定（2026-09-23 补登，#1 残值）**：元素在 seek 时刻仍带 GSAP from/to 偏移、压向安全线/画布边缘（入场偏移溢出）时，以 **instant_preview 像素实测**裁定——每场 `start+3.0` / `end-2.0` 两张截图是变换后实际形态，溢出即退出 2 阻断（`:827-830`）；**不增设静态代理门**：静态 HTML 解析看不到变换后布局，增设一门只会多一个与像素分叉的裁定面（与本节"判据函数不复制第二份"同族纪律）。

### 5.3 连续修复止损与换层判据（2026-10-21 加强）
- 同一问题连续修复 **超过 3 次** → 停止，输出阻塞报告
- 禁止在未获得用户新方向前继续堆叠修复尝试
- **「停止」不等于「结案」**：止损时第一件事不是写"无解"，而是判**当前这一层还有没有杠杆**。判据＝这一层操作的物理上限能否触及病灶——例如在音频里加静音，最多让声音"断得干净"，不能造出原本不存在的能量谷；在字幕层改时间，改不动合成时的发音。答完再决定：换层，或明确写"该问题在现有链路内不可解"。
- **同一处第 2 次修补仍不改善 → 判「本层无杠杆」，必须换层**；第 4 轮必须已经换到源头层。同一层连续三轮以上＝把成本花在同一堵墙上（2026-10-21 实证：下游四轮全部落空，第五轮回到源头一次即成）。
- **观感类问题以人耳结案，不以量化指标结案**。指标只回答"测到了什么"，不回答"应当怎样"；指标改善而人耳否决时，以人耳为准并回头查指标是否量错了对象。**禁止拿指标改善去说服用户接受观感**（本轮三次指标达标、人耳三次否决）。
- 分层次序（由近及远，代价递增）：下游后处理 → 强制停顿/切点参数 → 共享机制代码 → 源头重合成（付费）→ 换引擎。**每上一层都要先证下一层无杠杆**，而不是凭习惯从最近的那层一路试到底。

| **适用面** | 任何"量一句旁白里某两个字之间停了多少"的任务：句间停顿、词内停顿、pause_marks 声明核验、`--emit-declarations` 候选生成、外部片 TTS 节奏对照 |
| **陷阱一：插值时刻会造出 1.2s 的假停顿** | 形态：普查报出无标点位点最大 1.24／1.16／1.13s，若直接据此定阈值即把阈值定在伪影上。`_forced_align` 对 matched=0 的字符在左右锚点间**线性均分**时刻，未匹配段的两字之间"差"得再久也不是静音。本轮 8 枚最大读数**全部**落在 matched=0 上（`nopunct_two_legs.json` 腿A）。**防范**：凡以 `chars` 差值为判据的机制，准入第一条就是 `chars[i][2]==1 且 chars[i+1][2]==1`；未过该腿的位点计入"未裁定"，不得按 0 计、也不得入命中 |
| **陷阱二：ASR 时刻差 ≠ 静音（能量腿必须并行）** | 形态：35 个两侧实测的位点里只有 18 个是真静音谷（谷底 ≤-30 dBFS 且与两侧语音落差 ≥12 dB），其余 17 个谷底 -15~-29 dBFS——那是 Whisper 词尾早收造成的时刻偏差，**听上去根本没有停顿**。**防范**：动波形的机制两腿都要过；只点名不动波形的面可以把未过能量腿的位点列出来，但须单列计数（本仓落 `intra.unconfirmed`），不得与确认位点混进同一个 hits |
| **陷阱三：小句粒度的 A/B 会在整场粒度上翻转** | 形态：为验证"改文案能否消除词内停顿"，把单句送进引擎得 0.00s（干净），据此几乎写成"加连接词即修复"；同一句按生产粒度（整场 101 字一次合成）送进引擎，同一位点 **0.30s** 重现交付片形态。**引擎的韵律输入是整段，不是这句**，故小句 A/B 测的是另一道题。**防范**：TTS 侧任何 A/B 必须复刻生产的调用粒度（`step1_generate_tts` 每场一次调用、送整场旁白），并留一条"同文本 sha256 逐字节相同"的确定性对照——本轮正是这条对照（连合成 3 次字节全同）先证伪了"引擎随机"，才把结论逼到"上下文敏感＋跨时间不确定"这一准确表述上 |
| **陷阱四：探针的缓存键由标签中文剥离派生 → 七个候选共用一份 wav** | 形态：`re.sub(r'[^0-9A-Za-z]+','',tag)` 把中文标签剥成空串，七个 variant 落到同一个 `ab_.wav`，表里每一组读到的都是同一句合成——一度得出"所有改写都干净"的假象，且各组的 asr 文本彼此相同这一线索就在打印里。第二版键取 `label.split()[0]`，"s2 原样"与"s2 改写"又同键，sha 逐字节相同当场显形。**防范**：**缓存键必须由被合成/被处理的对象自身派生**（本轮改 `sha256(text)[:8]`），不得由人写的标签、路径片段或自然语言前缀派生；多候选实验须在结果表里带上每件产物的内容哈希，两行哈希相同即键失效 |
| **取证件不冒充交付物：画面二次编码会造出"背景不纯"** | 形态：给用户试听的两支对照件我用 `-c:v libx264 -crf 23` 重编码画面，crf23 把大面积平色压出色带，用户读成"黑色、灰色、白色多色系混合"。修复＝`-c:v copy`（视频流直拷）＋另出纯音频 m4a；核对方式＝同刻解码帧 md5 与成片逐位相同（本次三件同值）＋ `ffprobe` 的 codec/宽高/pix_fmt 一致。**防范**：任何"给人看/听"的对照件，画面一律直拷；只取音频的用途就别带画面 |
| **陷阱五（第四轮）：静音检测器会在清辅音内部触发，把"压停顿"做成"切字"** | 形态：为验证"静音占比是卡顿主因"这一假设，我按 5ms 帧峰值 < -30 dBFS 取静音段、把 0.15s 以上一律压到 0.08~0.12s，在 66.2s 音频上剪了 **36~42 处**——平均每 1.6~1.8 秒一刀。用户试听裁定"越改越糟，出现音频被不正常切断的突兀感"。读数本身在当时就已在手，却没有对照：**参考片同口径的句内可闻间隙只有 0.7 处/分钟**，即我的"静音段"绝大多数不是停顿，而是 s/sh/f/h/x 这类清辅音与韵尾能量自然跌落穿 -30 dB 的区间——峰值判据把"轻声"读成"无声"。**防范（两条都是结构性的，不靠小心）**：① 任何以能量阈值取静音的机制，命中频率必须与参照物同口径读数做**哨兵对照**，量级差 >3 倍即判取数面失效、禁止出件；本仓该读数已在 `rhythm_three_way_compare.json`，缺的是"交付前先读它"这道动作。② **判据须要求边界为真静音端点**（区间两侧若干毫秒内仍低于阈值、且区间内为局部能量最小的一段），而不是"整段低于阈值即静音"；8ms 淡变救不了落在音素内部的切点。**教训上位**：已验收通过的材料上做修补式对照件，风险是"把还能交付的东西改坏"——修不好就退一步交付原状，而不是继续加档位 | 
§5.9 的判据面新增一条**跨片比较**的防范（陷阱六，见下表）；
| **陷阱六（第六轮）：ASR 派生量在跨片比较上不可比** | 形态：同一份波形，ASR 词级腿给出"参考片静音 10.8% vs 本仓 26.7%、停顿频次差 32 倍"，而不经 ASR 的波形腿（连续 ≥0.20s 低于 −30 dBFS）给出 **25.2% vs 本仓中位 26.7%、28.2 对 27.7 处每分钟——无差异**。成因是分段粒度：ASR 把参考片 726.7s 切 451 段、把本片 313.2s 切 37 段，段内词间隙与 `speech_only` 都随切分形态浮动，**跨片读数不同源即倍数无意义**。更该记的是生产机制：第四轮已实测出该取数面定位误差 0.5s，**却没有回头撤销用它得出的相邻结论**；且分段数 451 对 37 就在同一份读数里，是口径不同的显形信号，没被读。**防范（结构动作，不靠小心）**：凡"本仓 vs 外部参照"的数值比较，先证两腿的分段／归一方式一致；不一致即改用于分段无关的取数面（波形／像素／字节），或判"无从比较"。参照对象的编码、说话风格、模型行为都不受本仓控制，**同一段代码不等于同一口径**。另一条同源防范：发现某取数面分辨率不足时，须同批列出"用它算过的相邻结论"逐条撤销或重测，否则旧结论会继续被下游引用（本轮 `agents.md`、§10.3、静音压缩判否理由三处同步就地更正） |
| **本批落点** | 判据与阈值住 `程序文件/脚本/intra_pause.py` ＋ `程序文件/配置/config/quality/audio_sync_rules.json → intra_pause_trim`；生效面＝`enhance_video_audio._trim_intrasentence_silence`（缺省关闭）；点名面＝`narration_pause_precheck.audio_face` 第三桶；锁定用例121 ＋ 变异 121-M1..M15（15/15 落对位，含一次 CRASH 被改写为数据无关的断言结构）。完整读数见 `外部参考片实测与借鉴裁定_20261105.md` §九 |

### 八·补：TTS 语速实测基准（`duration_budget` 声明的唯一估算口径）

**为什么单列一条**：`agent-decision-map`（2026-10-12）按"5.0 发音字符/秒"反推声明预算 235 s，成片实测 253.8 s，超预算 18.8 s 走 `--accept-over-budget` 放行留痕——偏差全部来自这个手抄常数，不来自内容超载（13 场 65–94 发音字符，已按每场 60–70 字基准收紧）。预算写低会让每一次正常交付都需放行，放行留痕便失去"异常情况"的含义。

| 口径 | 定义 | 实测值（qwen cosyvoice-v3-flash + `longanling_v3`，rate +5%） | 用途 |
|------|------|:---:|------|
| 纯语音率 | 发音字符 ÷ Σ(各场 TTS wav 时长) | **4.33 字符/秒**（1002 / 231.3；逐场 3.86–4.97，中位 4.28） | 估单场窗口下限、估句间停顿余量 |
| **成片折算率** | 发音字符 ÷ `video_duration` | **3.87–3.95 字符/秒**（三样本：`agent-decision-map` 1002/253.8=3.95、`standard-system-explainer` 1221/313.2=3.90、`prefab-decor-delivery` 1576/407.6=3.87） | **声明 `duration_budget` 用这一档，取 4.0 作上界** |

**读法约束**：①"发音字符"＝归一化后保留的发音字符数（`cue_resolve.normalize` / `_forced_align._normalize_chars` 口径），**不是**源文本 `len()`——标点与空格不进 TTS 时长；②两档之间差的不是语速而是**留白**（本片 13 场合计约 19.5 s 场景窗口留白＋3 s 封面），所以"4.3 字符/秒 + 每场留白"与"4.0 字符/秒"等价，选用哪档取决于是否已逐场排窗口；③换音色/换 `qwen_model`/改 `rate` 后本表数值不适用，须用当轮 `_timeline_manifest.json` 的 `tts_duration` 重算，不得沿用到新项目；④**排完窗口觉得"每场说完还空一下"时，收紧入口是 `shrink_basis`，不是调小 `shrink_margin`**——那 2 s 听感留白由"设计值 1.5 s"＋"wav 尾部静音 0.31–0.46 s"两段构成，前者是本参数动不了的、要动须另一次裁定，后者可由项目 config 顶层 `"shrink_basis": "speech_end"` 收回（本片实测 4.66 s＝片长 1.84 个百分点）。判据与缺省为何未翻住根治理文件「场景余量的基准」节，本处只放指针不复述。

**反例（禁止）**：按参考片或经验"每秒 5 字"反推预算；把 `len(narration)`（含标点）当分子。

**关键发现**：成功项目的 subtitle-safe 高度均在 130-140px，而医院项目膨胀到 325px 是编译器内容溢出控制的失败，不是 safe-zone 设计的问题。
