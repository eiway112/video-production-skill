## 归档文件（`_归档/` 目录）

历史复盘和分析报告，结论已沉淀到 AGENTS.md 或脚本中。需要追溯时可查阅，不参与日常执行。本目录未携带 `_归档/` 时，以下两条只作口径说明。

- **状态声明集中写在此处，归档本体一字不加**：归档件是**时点快照**——里面的参数基准、引擎口径（如 Edge-TTS/cosyvoice）、门禁清单、目录结构描述都可能已被后续机制取代。引用其中任何数字或写法作现行判据前，必须先核 `AGENTS.md` 与现行模板；对不上时**以现行载体为准，不回改快照**（改掉旧文档就毁掉了"错误当时如何产生"的证据）。
- **归档动作的边界＝非跟踪对象**。此处两条路径不得混为一谈：
  - **本目录 `_归档/` 受 git 跟踪**，历史分析文档移进来不丢可追溯面。
  - **`过程产物/_归档/` 不在 git 里**（`.gitignore` 整棵 `过程产物/` 拒绝）。修订递增时把旧版搬去那里的，
    **只准搬成片 mp4 这类不入 git 的对象**；交付说明 md 与字幕 srt 是跟踪小文件，必须留在 `成果文件/`——
    搬过去等于从可追溯面删除，修订链的版本化依据即断（2026-11-06 修订链实证）。

## 基本原则

- 最终 MP4 才是验收事实，预览和截图只作为中间证据。
- 用户提供的 Logo、产品图、施工图、报价表、案例照片默认不得重画、替换用途或改变含义。
- 先做 30-60 秒短视频模板，跑通后再扩展到 3-5 分钟培训或课程视频。
- 每次返工都要转化为规则、组件或清单，避免下次重复踩坑。
- 动效必须有精确的时间参数（持续时间、缓动曲线、触发顺序），不允许只写“淡入”。
